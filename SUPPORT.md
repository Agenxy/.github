# Getting help

This is the default for Agenxy repositories. A repository with its own
`SUPPORT.md` supersedes it.

| You have | Go to |
|---|---|
| "How do I…", "should this…", thinking out loud | the repository's Discussions tab |
| Something behaved differently from what it said it would | open a bug |
| Something the project should do and doesn't | open a feature request |
| A security vulnerability | **not a public issue** — see [SECURITY.md](SECURITY.md) |
| You want to change the code | [CONTRIBUTING.md](CONTRIBUTING.md) |

Check whether the project ships a `doctor` command before filing. Several do,
and they name the fault and the fix in one line.

## What to expect

These are small projects. Issues get read; they do not always get fixed
quickly, and an issue nobody has replied to has not been ignored on purpose. If
something is blocking you, say so — it changes the order things get done in.

There is no commercial support and no SLA.

## Reading order

Every project is listed at [agenxy.org](https://agenxy.org), and each has a page
there describing what it does and what it does not do yet. In the repository
itself, the README says what it is and how to run it; where a `PHILOSOPHY.md`
exists it explains the design decisions people ask about most.
